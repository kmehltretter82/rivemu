# Superblocks, fetch fast TLB, cheaper chains (2026-11-03)
#
# Why: CI run 41623958358 (8247296) measured the P17 single-hart median on
# macos-latest at 8.794 s (p95 10.729; base 23.952 s on the same runner):
# above the < 8 s target. The head/base ratio on macOS had stayed at about
# 0.37 since aedb252 while on the x86 Ubuntu runner it fell to 0.28.
#
# 1. Apple numbers (CI job p17-variants, since removed; same binary, an
#    environment variable selecting the variant, alternating):
#    scripts/interp-microbench.py, guest MIPS (median of 3):
#                          run 41629502068     run 41631138989 (slower runner)
#      dependent adds       488 -> 662 fwd      346 -> 498 fwd
#      independent adds     718 -> 617 fwd      494 -> 480 fwd
#      addmul_1 loop        410 -> 435 fwd      342 -> 323 fwd
#    P17 SMP1 median (9 samples each): 7.480 s vs 7.432 s with forwarding;
#    9.843 s vs 9.939 s on the slower runner (samples 8.7 to 13.3 s there).
#    A dependency through Hart::x costs about a third on Apple, and keeping
#    the last result in a host register (RIVEMU_BLOCK_FWD) removes that,
#    but the P17 boot does not change: few kernel instructions depend on
#    the one before. The experiment is removed.
#
# 2. Where the P17 boot's time goes: scripts/p17-callgrind.sh (the Debian
#    boot to /init's poweroff under callgrind, -icount shift=3) in CI run
#    41631138989: 93.6 G host instructions for about 1.9 G guest
#    instructions. The dispatch line 13.2 G, the block loop 9.9 G, register
#    reads 9.4 G; the step between chained blocks about 11.6 G over a dozen
#    lines (blocks averaged about four guest instructions: every
#    conditional branch ended one); translate_with_ram_off 2.5 G (block
#    chains into another page took the full translation); sfence_vma 1.2 G.
#    RIVEMU_PC_PROFILE now records host time per guest function too
#    (scripts/pc-profile.py prints MIPS per function): on the from-source
#    Linux boot, crypto and RAID loops run at 200 to 350 MIPS, generic
#    kernel code (spinlocks, rwsems, kernfs, vsnprintf) at 65 to 90 MIPS.
#
# 3. Changes (21acfa8):
#    - Superblocks: a conditional branch no longer ends a block; a taken
#      branch leaves it (exec_inline returns Next / Jump / Slow).
#    - A fetch table in each fast-TLB slot for chains into another page.
#    - The fetch page cache holds only pages the decode caches can tag, so
#      the chain lookup drops two checks.
#    - Op::Illegal moved behind the inline operations: the jump table
#      needs no offset.
#    Host instructions, deterministic from-source boot (OpenSBI + Linux 6.12
#    to RIVEMU_SMOKE_OK, -icount shift=3, callgrind, local):
#      22,996 M  before
#      22,502 M  fetch table
#      21,671 M  + chain checks, experiment removed
#      21,382 M  + jump table from 0
#      20,341 M  + superblocks                       (-11.5% in total)
#    The P17 Debian boot itself (CI job p17-callgrind, same -icount):
#      93,576 M  4ac6530 (run 41631138989)
#      79,529 M  21acfa8 (run 41636562098)            (-15.0%)
#    Tried and reverted: an iterator instead of the index in the block loop
#    (21,717 M, +0.2%); an exhaustive match in exec_inline (21,161 M, +4.0%,
#    as before).
#
# 4. Checks: all workspace tests; new blocks_with_inner_branches_match_
#    single_stepping (catches a wrong count on a taken exit and a taken
#    branch that stays in the block) and block_chains_across_pages_follow_
#    remaps_and_privilege (catches a fetch lookup that ignores the epoch and
#    a fill that leaks into another context's slot); riscv-tests 244/244;
#    riscv-arch-test 1251/1251; Linux device E2E 6/6 (local, 28 s).
#
# 5. CI run 41636562098 (21acfa8), p17-bench, 9 samples each, head vs base
#    (main) on the same runner:

#      head SMP1 median 6.224 s, p95 7.670; samples 7.670 7.478 7.081 /
